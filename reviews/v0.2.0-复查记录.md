# v0.2.0 知识完整性与可用性复查

日期：2026-11-15。目标：让不了解课程的执行 AI 能依据通用知识和客户资料生成业务模型实施方案，并按步骤找到输入、方法、产物、检查和接续位置。

## 发现的问题与修订

| 原 v0.1.1 的缺口 | 对使用的影响 | 本轮修订 |
| --- | --- | --- |
| K1–K12 主要是概念速查 | 知道术语，但对提取语境、身份、事件、时间、规则和接入缺少操作判断 | 新增 E1–E4 深入知识卡，包含判断步骤、易错例及本项目学习产出 |
| 只有背景、模型、过程记录，没有实施方案 | 执行 AI 需自行猜任务分解和完成条件 | 新增 08 与实施方案模板，映射知识、输入、产物、角色、检查和阻塞处理 |
| 新项目需要反复说明多个路径和文件 | 启动与接续容易丢版本或停点 | 增加可选 init／status／check，保留已有文件并登记位置和证据索引 |
| 示例侧重完成后的模型，未展示如何规划 | 不易看出怎样生成客户专属方案 | 新增设备维修方案示范，处理重复事件、状态混用、缺证据和无运行环境 |
| 结构验证曾只有临时人工脚本 | 迁移、断链或完成状态缺证据不易发现 | 增加可重复运行的结构检查与辅助工具行为测试 |
| README 缺少完整流程图 | 不易先形成全貌 | 按用户要求加入原图并标注课程语境与指标库能力边界 |

## 知识范围核对

按任务与范围、角色取证、材料与提取方法、身份与对象、关系与时间、规则与流程、证据与未知、模型组织、独立测试、Agent 接入与判读、变更回归、后续指标衔接逐项对应。各项的方法、学习产出及写入成果位置见 [08](../08-实施方案与学习路线.md)。

这是业务建模闭环的方法覆盖。客户行业事实仍需取证；指标库完整实现仍在后续模块范围。未使用课程人物、阈值或案例规则代替通用定义。

## 场景走查方式与边界

本会话依据明确的虚构 R1–R5 材料，按新版知识与模板编写设备维修实施方案，并回查重复派工、完工与验收、未知和无运行环境的处理。它展示能写出的方案结构，属于同一会话的案例演练与自查。

这不是独立新 AI 的盲测，也未运行客户 Agent。器材借用示范中的 8 道题和设备维修示范中的测试方向仍是 expected，不能登记为实际回答通过。
