# 业务模型到指标库的交接入口

**v0.7.0 起已提供完整方法模块：** [13 构建手册](../指标库/13-指标库建立手册.md) → [14 测试与排查](../指标库/14-测试判定与证据排查.md) → [15 验收与 ETL 交接](../指标库/15-验收与ETL交接.md)。本页保留旧路径和上游交接约定。实际生成与运行由执行 AI 使用客户环境完成；没有新增通用指标引擎，也没有客户验证通过结论。仅交付业务模型的任务仍按其自身范围验收。

## 业务模型可以交出什么

对象和身份、关系与角色、时间条件、业务规则和例外、使用场景、原始依据、未知与确认记录。模型以具体版本交给后续工作，避免后续实现引用不明版本。

## 还需要另外取得什么

| 后续输入 | 要说明到什么程度 |
| --- | --- |
| 指标用途与问题 | 谁用来做什么判断，不能只给一个名称 |
| 计算口径 | 数谁、时间窗口、范围、条件、聚合、去重、单位、空值／零与例外；比率另明确分子分母 |
| 数据字典与样本 | 每条记录代表什么，字段含义、识别与关联依据、覆盖和质量；样本规模按要验证的风险决定 |
| 独立核对依据 | 可从同批原始记录按明确口径另行推导，包含能暴露错误的例子 |
| 目标工具与约束 | 实际使用什么计算或语义工具，要求什么格式；不能由课程案例默认选型 |

## 接续模块覆盖什么

指标定义与审阅 → 数据映射和粒度判断 → 必要派生数据 → 目标工具的语义与指标配置 → 独立计算验证 → Agent 查询与解释 → 变更回归。

是否需要 measure、metric 或特定语义层取决于采用的工具；具体语法、版本与调用方式在实现时依据该工具的官方资料核对。不能把一种课程架构当全部客户的固定方案。

## 交接记录

可直接用[访谈到模型交接模板](../../templates/访谈到模型交接.md)第三节：每个指标待办引用模型版本／条目、核查取舍及原始依据。候选可登记，未确认的业务条件不能直接写成正式指标；无指标需求时说明不适用。

在客户项目中记录：对应业务模型版本／指标候选及用途／已有口径与来源／未核条件／可用数据／独立依据／下一步。现有对象与业务规则引用业务模型；新增或改变业务含义时回到模型核查，避免两处各写一套相互矛盾的定义。
