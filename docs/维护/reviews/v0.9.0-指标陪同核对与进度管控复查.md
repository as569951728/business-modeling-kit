# v0.9.0 指标陪同核对与进度管控复查

用户反馈：一次性执行完整指标库后，虽有进度报告，自己仍不认识指标，也无法据此与业务现场沟通，需要 AI 主动邀请核对并保留进度控制。

## 原因与调整

原 13 强调已有范围连续推进、只把必要问题交给用户，缺少“材料齐全时也讲解核对”的停靠点。本次将默认协作方式改为分批陪同核对，阶段编号和技术标准不变。

- 先给完整业务用途分组与拟议批次，再展开小批（通常约 3 项）；每项提供白话含义、算法、时间范围、来源、例子、用途限制和业务待问。
- M1 口径、M2 代表性独立样例、M5 结果／M6 交付前均先准备可审材料，再主动请本人处理；未取得回复不跨过依赖。
- 已核批次内构建、加载、测试与技术修复连续执行，不让本人审代码或手填所有 expected。
- 核对记录绑定条目、批次、版本与真实回复；已展示、本人核对、技术通过和业务签署分开。
- 老项目先保留成果与实际证据，补最早未完成核对；实质规则变化再评估重建／复验。明确委托连续执行的范围可单独登记。
- 方法集中原 13；同步 AGENTS、首页、开工话术、14／15、11、两份模板和维修示范，避免不同入口绕开核对。

## 作者文档情境走查

以下检查规则能否给出明确动作，不是独立 AI 实际运行测试。

| 情境 | 应有行为 |
| --- | --- |
| 用户只给旧的“按工具包构建验证”指令 | 默认先全景与首批口径核对，不直接整库执行至 M6 |
| 所有资料齐全、无异常 | 仍主动讲清和核对指标，不仅缺证时问人 |
| 用户只说看到了或暂不回复 | 保持待核，不因时间经过继续依赖工作 |
| 用户明确确认当前展示批次 | 只作用于该批该版本，不扩展到未展示指标或未来核对点 |
| 用户看不懂公式／expected | 用原记录与计入排除例子解释，接受自然语言处理，不强制考试 |
| 本人同意推进，但缺客户规则依据 | 事实仍待核，确认流程不填补事实 |
| 样例已核，进入技术步骤 | AI 连续完成已核批次的适用技术工作，结果阶段再主动复盘 |
| 口径实质变化或只改无语义影响的代码 | 前者回受影响核对点；后者按原授权修复回归并汇报 |
| 已有技术成果、尚无本人核对 | 保留产物和结果，当前主线补最早核对；不倒填、不盲目全重跑 |
| 用户只要求审现有结果 | 用适用证据准备复核，不自动启动新客户调用 |
| 用户明确委托某一批连续执行 | 保存原话及范围，仅在该范围调整停靠点，不视为客户签署 |
