- 只了解项目不自动实施；已有成果保留，补缺失讲解和实际核对，不倒填用户掌握、业务确认或运行结果。

## 能力边界

样稿是可交互的静态页面，未接客户项目、AI 服务或持久化；选择只在本页，导出不等于已交回、已采用或已签。反馈包含示范标识、条目、版本、原话和草稿状态。未来接入实际项目需先确认页面与反馈流程，再验证写回、重载及旧版本冲突；当前不宣称这些能力已实现。

没有改变 kit.py、测试辅助代码、S／M 编号与既有客户登记。未迁移或运行客户工程，未修改独立工作台，未发送访谈问题。页面使用已公开虚构 MR 示例，无客户资料。

## 方法作者走查

以下是文档规则走查，不是独立 AI 行为测试：

| 输入情境 | 应有处理 |
| --- | --- |
| “了解下这个项目” | 只读现状与路线，不初始化／写客户文件／建库／测试 |
| “按工具包建立指标库” | 先交全景现状；后续逐小步交付，不能到 M6 才请人看 |
| M2 已核对 | 可按下一步指令进 M3；M3、M4、M5 分别交付解释，不一口气连跑 |
| 本人“不懂这个定义” | 先解释含义、例子和依据，状态不自动推进 |
| 多签认事实未知 | 准备二次问题和影响，不让用户点选虚构业务事实 |
| 收到业务口述 | 保留原话及范围，再判断核实／采用／回归，不自动关闭所有关联项 |
| 旧项目已有技术成果 | 保留成果与失败，补最早欠缺的讲解、复核，按变更判断是否重做 |
| 页面反馈尚未交回 | 显示草稿，不登记项目已保存、用户已掌握或客户已签 |
| 用户明确委托具体一段 | 记录对应范围可连续，未覆盖部分仍逐步，事实与权限仍取证 |

真实客户数据可读性、用户实际体验、独立 AI 遵循能力和持久化反馈链路均未验证，不能以本页自查替代。
