# v0.8.1 验收证据与签署准备复查

用户要求确认业务模型和指标库是否留存足以支持业务签署的验收证据。复查发现原 12／15 及模板已有范围、版本、原始来源、独立标准、实际运行、回归和复核记录要求，但缺一个共同的签署材料编排与固定归档办法。

## 已补齐

- 16 共用方法和一份证据包／签署记录模板，两类技术验收仍各自按 12／15 判断。
- 项目验收条目→交付版本→检查／用例→实际证据→遗留及复核结论的对应。
- 固定批次／修订、快照或不可变记录、内容校验标识及接收环境可访问性；内部原件和对外副本分别保存。
- 一页业务摘要与附件、实际签署身份及范围依据、日期／方式／原始记录，明确未取得签署不写已签。
- 技术结论、签署准备和业务签署分层，旧签署不得自动覆盖新成果；保管与保留按项目已有约定，不擅设期限。
- 原“按工具包组织测试验收”入口直接组织材料，不额外要求用户复制长指令；不自动发送或代签。

## 文档负例走查

以下是作者核对规则是否能拒绝不成立结论，不是实际客户测试：

| 情形 | 方法要求的处理 |
| --- | --- |
| 只有总结或通过率截图 | 查适用原始结果与核算证据，缺少则列缺证 |
| 模型与测试对应不同版本 | 核关联与影响，不能把旧结果直接用于新交付 |
| 填好了签名和日期模板但未取得确认 | 保持未取得，不能用 AI 草稿代替签署 |
| 修改已签附件再沿用旧签署 | 保留旧包，形成修订并按约定复验／确认 |
| 附件仅有编制者电脑路径 | 改成包内路径或约定可访问记录，并检查接收环境 |
| 缺签署代表范围或业务确认依据 | 列待核，不根据职位自动推定 |
| 为对外方便覆盖内部原件或复制全部数据 | 保留原件与副本对应，只纳入本次需要且允许的内容 |
