2026-11-16。用户看到“建议采用／带条件采用／暂缓”等标签后，不清楚如何回应，希望 AI 给处理建议，自己选择或直接打字说明。

## 改动

在 [04 第 3 步](../../建模/04-业务模型建立手册.md)补入解释、推荐、理由、影响、选项／自由输入和回复落实规则；增加[候选处理单](../../../templates/候选处理单.md)，关联入口、提炼与交接。复用既有步骤，不另建阶段，不要求用户逐条重复审批。

“带条件”拆成已有适用范围与尚待满足前提；同意处理方式不能填补外部证据。批量回复绑定清单版本及条目，新增信息保留提供者；截图中的计划性回复不等于实际写入。

## 内容自查情境

下表为作者对方法的文字自查，非独立 AI 运行结果，数字和业务完成状态均不从用户截图带入本包。

| 输入情境 | 应如何处理 | 应判不合格的处理 |
| --- | --- | --- |
| 用户不懂“带条件采用” | 解释本条究竟是哪种条件，给拟处理句子、依据和影响 | 只再次解释状态名字，让用户自己猜动作 |
| 只有组内做法，项目解释内部月报 | 可推荐按原来源及组内范围保留，其他部门未知另记 | 用户选 A 就升级为全公司制度 |
| 数字本身听不清且无其他依据 | 推荐回听或找可说明者核实；未核之前保留歧义 | 让用户在两个数字中按偏好选一个当事实 |
| 用户批量同意“建议采用”组 | 绑定当时清单版本及明确编号，继续已授权工作 | 自动覆盖条件项、暂缓项或后续新增项；或要求全部重新审批 |
| 用户自由回复“保留组内做法，财务待核” | 映射到具体条目并记录原话，明确就落实 | 要求用户再改答 A；或写成财务已确认 |
| 用户说“这个词我不懂”／界面仅预选 A | 继续解释，保持未作取舍；其他明确部分可继续 | 当作同意并登记采用 |
| 用户回复对象确有歧义 | 只核受影响部分，不扩大采用范围 | 猜测对应全部条目，或阻塞全部已明确工作 |

虚构原文 T1 与 A／B 示范写在 04 中，声明仅用于交互展示。方法区分选择、实际修改和业务核实，不暗示用户承担全部逐字提取检查。
