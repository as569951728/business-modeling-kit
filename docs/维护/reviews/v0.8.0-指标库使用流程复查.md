# v0.8.0 指标库使用流程复查

依据用户 2026-11-18 请求，复查指标库的可用性，重点是使用简单。对象为原本地 v0.7.7 的入口、13–15、项目接续、三份指标模板及维修示范。完整专业知识仍供 AI 使用，用户的操作负担通过入口和交互收拢。

## 问题与处理

| 发现的问题 | 实际影响 | 本次处理 |
| --- | --- | --- |
| 首页列出多种细分技术任务 | 用户仍需知道 expected、judge 等词才能选入口 | 日常显示开始／继续／测试验收；详细方法折叠，原链接保留 |
| 各处要求读知识，但未明确不同模块的最短接手路径 | 已有模型的指标项目容易重做背景、读错 S 阶段或停在方案 | AGENTS 按模块读取；13 明确首轮盘点和连续推进范围，11 指向正确指标入口 |
| 指标进度靠 AI 维护，但缺少固定成果索引和客户入口指引 | 换会话容易找不到材料、重复问背景 | 默认复用指标实施进度为唯一入口；补工具包位置、成果链接和原项目接续引用 |
| 进度模板开头是背景与技术适配 | 用户先看到大量待填信息 | 四行简报、成果索引、关键待办移到前面；模板由 AI 按需形成 |
| 缺数据或环境时，继续什么和问多少不够明确 | 容易把技术配置交回用户，或整体停住 | 先查代码和资料；只问改变方向的少量关键问题，推进独立子项，未运行如实保留 |
| 多指标只有整体 M 阶段，缺逐项或批次进度 | 一批通过可能被误读成整库完成 | 原定义清单补指标／批次／依赖／证据与下一动作，主入口引用，不复制口径 |
| 模板内相对方法链接离开工具包可能失效 | 客户项目里的检查入口打不开 | 要求实例化时改实际引用并核查；临时项目验证迁出后的引用 |

## 场景走查

以下是作者按文件逐项走查，不能称为独立 AI 使用测试：

| 情境 | 合格行为及对应依据 |
| --- | --- |
| 只给未分类材料和一句目标 | 13 首次接手：AI 盘点、先交简报，不回传空模板 |
| 已有业务模型和若干指标 | 13／AGENTS：复用已有来源与取舍，只补当前所需缺口 |
| 用户只说继续 | 13 单一入口及 11：识别模式、读入口和证据，不重建登记 |
| 只问现在到哪了 | README／快速开始／13：只读汇报，不启动新执行 |
| 有资料但无运行环境 | 13：可做设计与核查，环境和真实运行保持未完成 |
| 多指标、部分口径待核 | 13／定义模板：完整范围保留，独立指标分批推进，整轮结论不偷换 |
| 不懂业务定义或处理标签 | 13／AGENTS：白话依据、建议和影响；事实不足推荐核实，不让用户猜选 |
| 组织测试验收 | 15：读细则、核准备、按权限真实运行、回归、分层结论；缺证不通过 |
| 新数据或共享定义变化 | 13／14／15：按依赖标需复核，保留历史，真实复验 |
| 换项目或复制模板 | 13／模板索引：保留原文件，实际链接有效，不把本包示范当客户事实 |
