# 指标库验收与 ETL 交接

承接 [13](13-指标库建立手册.md)的 M6，使用[测试与验收记录](../../templates/指标测试与验收.md)。本章给通用完成判据，不替代合同或客户已约定的验收责任；已有更严格要求沿用并注明。

## 一句话入口：按工具包组织测试验收

工具包和客户项目已在上下文中时，用户只需说“按工具包组织本项目的测试验收”。AI 自行按下列流程读取和落实细则，不要求用户复制长提示词、选择章节或先填写用例。首次使用仍需知道工具包与项目位置，已有登记直接沿用。

本入口默认按 [11](../项目协作/11-工作进度与接续.md)逐步陪做：先交现状、证据缺口和路线；用户指示后，每次完成下列一个有明确成果的小步及其必要检查，交付解释后停。完整范围不等于一次执行到底。核对页沿 [17](../项目协作/17-可视化核对与逐步反馈.md)，同时遵循 [13](13-指标库建立手册.md)的三个深入核对点。先核本人是否审过本批口径和代表性标准；无相应记录先用现有产物补可审材料，保持待核，不能把“组织验收”解释为免核直跑。M5 结束后主动解释结果、失败修复、环境限制及拟议交付，取得本批复核再推进下一批或 M6 收尾。用户复核、技术通过和客户签署分别留证；已明确同版本同范围的确认直接复用。

1. **核当前任务。** 读项目进度、范围、已核业务模型与口径、现有产物和验收约定；按 13 定位最早未完成项。请求验收不代表已到 M6，更不代表前置步骤完成。若当前对象是业务模型，转到 06／12 的对应方法，不混用指标判据。
2. **补齐可检验的标准。** 按 14 六项标准复用、检查或完善测试集、独立 expected、来源和项目专用 judge，执行适用正反自检。保留原测试与已冻结基线；新增标准引用依据，不抄待测结果。业务未决给核实建议，已明确部分继续推进。
3. **检查执行条件。** 核目标版本、数据快照、实际入口、环境和操作范围。只有设计或缺少可测版本／环境时如实停在相应节点，完成不受缺口影响的准备；不伪造 actual，不自行扩大客户动作权限。已有明确授权直接使用，无需重复询问。
4. **运行并留证。** 在已授权测试环境复用运行器完成加载／结构检查和本轮要求的真实问数、判定及解释核查，保存版本、输入输出、差异与 trace。已有证据核验适用版本后可复用；不匹配或受变更影响时补跑。
5. **排查与回归。** 按 14 保留失败、定位来源、评估影响，在既有任务授权内修复并执行约定回归；需改变业务规则、范围或其他未授权动作时，向用户给证据、建议和影响。未修复、未运行和待确认分别列出，不靠删题或改期望消除失败。
6. **给结论并接续。** 按本章 MA01–MA08 和项目既有约定给分层结论，复用原测试与验收记录。每次回复先报节点；先交一页摘要，详细方法与证据留文件。只有本轮要求和必要复核均满足，才登记对应层次通过。流程下一步来自实际未完成项；ETL 交接仅在当前任务包含时开展。

“检查测试是否合格”主要审核测试质量；本入口组织准备、执行、排查与验收全流程，默认分步交付，由用户逐步指示。两者都须守住当前范围，但不能因为旧的检查指令写着“仅检查”，就把已授权的完整测试任务缩成文档建议。技术结论、客户签收和生产授权仍分别取证。

## 先界定验收什么

记录本轮目标、指标／问题清单、数据及时间范围、支持维度与筛选、交付层次、必须项、方法／库／测试版本和既有复核约定。可以分别交设计、构建候选、可加载库、实际问数能力；不同层次分别给结论，不能把设计完成扩大成系统可用。

| 编号 | 必须核查 | 证据与典型不通过情形 |
| --- | --- | --- |
| MA01 范围与口径 | 关键定义、来源、单位、时间、适用范围、未知和采用记录 | 指标名齐全但核心规则缺证，不能验收为正确实现 |
| MA02 数据与映射 | 快照覆盖、粒度、身份关联、生效条件、缺失及质量影响 | 连接放大、缺关键表仍静默当零，相关任务不能通过 |
| MA03 方法与产物 | 实际生成输入输出、方法版本、完整依赖与来源 | 只修最终 SQL 未回补方法，不能证明可重复构建 |
| MA04 实际加载 | 目标版本的结构／编译／加载证据、运行环境标识 | 仅有文件或旧检查报告，不能声称当前可加载 |
| MA05 独立测试 | 标准来源、判定自检、真实结果、覆盖及失败处理 | 无运行、复制 actual 为期望、判定放过错误不能通过 |
| MA06 问数与解释 | 本期要求的真实使用入口、完整条件、结果、单位与解释 | 数值对但解释错；只跑独立 SQL 而本期要求 Agent 问数 |
| MA07 版本与回归 | 依赖影响、原失败与修订、约定回归、未覆盖说明 | 只测新修一题，未证明原有任务仍正确 |
| MA08 交付与责任 | 可复跑说明、限制、必要复核和下一阶段责任 | 技术通过不能替代需另取证的客户签收或业务收益 |

与本轮交付无关的项标“范围外”，本轮内确实不适用的项须有理由；缺材料、缺环境不算不适用。结论用通过／未通过／待验证／需复验，并引用实际证据。必须项存在关键失败或缺证时不能靠总体高通过率宣布通过。

本包这些判据由 AI 整理、FDE 按约定复核；没有自动验收引擎。声明限定版本、范围和环境，不保证所有未来业务或跨行业适用。

## 让 AI 先交一页结论，再链接详细证据

用户不必逐页翻日志。AI 依据已有记录汇总以下六项，详细报告和来源用路径／记录 ID 引用，不另抄整套材料：

| 一页要点 | 必须说清 |
| --- | --- |
| 验收对象 | 哪个版本、数据快照、环境、指标／场景、时间与维度范围、本轮交付到哪一层 |
| 已完成 | 模型口径、构建方法、加载、独立测试、真实入口和解释分别有什么证据 |
| 覆盖与结果 | 设计／已运行／通过／失败／未执行分别多少及对应规则；不能只报通过率 |
| 问题与限制 | 哪些阻断本轮必须项、哪些非阻断项可按既有约定保留；影响、责任和处理依据 |
| 分层结论 | 设计、可加载、实际使用分别给状态；需要的复核是否真实完成，未取得签收另记 |
| 下一步 | 还差哪一项才能完成，或应交给哪个后续环节；说明交接材料及反馈路径 |

“样本验证通过”“约定任务技术验收通过”“客户签收”“生产使用／业务收益”各需各自证据。前一层通过不能自动升成后一层。非阻断问题的保留按已有约定记录，不默许接受，也不重复索取已有授权；关键失败和必需证据缺失仍阻断对应层通过。不能在发现失败后悄悄删题或缩小范围来达标。

测试都通过时仍检查规则覆盖和解释：六道相近问法全部通过，不代表六项不同业务规则已验证。只用合成小样本也不能证明真实数据完整、实际规模性能或生产权限隔离。

## 留作业务签署依据的证据包

按 [16 证据留存与签署](../项目协作/16-验收证据留存与签署.md)把项目验收项、MA 检查、模型／口径、实际构建库、独立标准、真实结果与回归关联起来，固定同一批次的版本和证据索引。AI 自动纳入本章的验收收尾，不要求用户另整理日志或提出一段长指令。

保留内容／技术结论、签署材料准备和实际业务签署三种状态。对外一页摘要引用约定可访问的附件，内部保留来源和原始记录；没有签署依据不能写已签，变更后不沿用旧签署覆盖新成果。若本轮仅做技术验证或草稿，仍按已有范围留证，不强制启动对外签署。

## 交给数据清洗工作的内容

业务模型说明含义，指标定义说明需要什么计算事实；ETL 据此准备可靠数据。将下面内容交给现有 ETL 流程，不复制它的方法正文：

- **业务与指标基线**：模型、口径、采用／未决版本，不能让清洗人员凭方便补业务规则。
- **输入与目标结构**：原文件／表、字典、行粒度、身份／关系、单位／时区／端点、目标字段和必须保留的原始值。
- **质量问题与影响**：问题记录位置、影响哪些指标、最低修复要求、暂不能计算的范围；区分已知格式错误与未知含义。
- **转换职责**：格式、编码、类型、重复处理、历史关系与业务派生各由哪一层负责；同一规则只维护一处并引用，避免 ETL 与指标 SQL 各写一套。
- **验证基线与回流**：独立样本、计入／排除、行数／键／金额对照、失败样本、所需回归；清洗后新快照与版本如何重新独立核算、加载和测试。

已有 [etl-utils](https://github.com/as569951728/etl-utils) 时读取其当前入口和项目约定再接续；没有该包时按项目现有 ETL 方案承接。这是方法连接，不是假定已安装、已同步或已运行。需要新的连接／权限时按本项目授权处理，不把指标交接当操作授权。

**交接不必等全部运行验收结束：** M1 已确定的数据需求可以先交 ETL，若数据缺口阻塞 M4／M5，则交接设计基线和失败／未决证据，状态保持待验证。数据准备好后回到独立核算、加载和真实测试；不能把“已经交给清洗”登记为指标验证完成。学习顺序与工程依赖分别记录。

## 变化如何回到正确环节

| 新发现 | 回哪里处理 |
| --- | --- |
| 日期字符串、编码、类型格式问题，含义已确定 | ETL 处理规则；验证转换未改变含义 |
| “完成”其实分报完工与验收，原含义不清 | 业务来源／模型和 M1 口径，再评估下游 |
| 数据版本或覆盖变了 | 独立期望按新快照复核，重新加载与实际测试 |
| 语义层或执行版本变了 | 适配约定、生成定义、结构检查和全链路回归 |
| 新增指标／维度／动作需求 | 明确新范围，分析共享依赖，不从原验收自动扩展 |

AI 更新指标进度和交接记录，保留旧结论及其适用时点。纯学习复盘可以更新方法与示范；不会自动改变客户模型、验收或合同基线。

## 可直接交给 AI 的收尾指令

> 按本章和当前项目既有范围／验收约定，先生成一页交付结论，链接对应证据，不要求我先整理日志。分别说明设计、加载、独立测试、实际问数与解释的完成情况，列出阻断项、可按约定保留的问题、未覆盖和未执行。没有证据不写通过，不把技术验证当客户签收。再按已核业务含义、指标定义和数据问题准备 ETL 交接，写清目标粒度、转换责任、核对基线及新数据回流后的重验步骤；用户需要判断时给依据、推荐处理和影响。同步指标进度，保留旧版本与实际结论。
