# 资料盘点、访谈取舍与成果交接

目的：把散落材料变成有依据的认识和少量重点问题，访谈后能接到模型及指标待办。详细记录由 AI 维护，现场保留两页。这里的编号、模板及默认问题数是工具包方法，不是课程或客户新增要求。

## 先看使用路线

识别情境 → [资料盘点](../../templates/资料盘点.md) → 每项取得标准 → 问题取舍与排序 → [访谈准备](../../templates/访谈准备.md)及两页现场版 → QC01–QC10 检查 → 按项目方式访谈 → [交接表](../../templates/访谈到模型交接.md)。

沿用已有同等记录，不复制重复台账。资料和来源判读先学 [E1](../知识/材料提取与证据判断.md)，客户说话方式参考 [02](02-客户访谈技巧.md)，现场版式参考 [03](03-现场Checkpoint.md)。不要让用户先完成这些模板才能开始。

## 1. 分清互动情境与协作方式

这两件事分别判断：真实访谈也可能是学习任务；角色模拟也可由 AI 辅助整理。`kit.py` 的 plan／learn／execute 仅辅助接续，不能替代下列情境记录。

| 互动情境 | 可用信息与可以索取什么 | 怎样记录、遇到拿不到时怎么办 |
| --- | --- | --- |
| 真实业务 | 本项目已给资料、实际岗位说明、授权范围内可看的原表／屏幕／记录 | 区分原件、现场观察、口述与转述；留人、时间、范围和来源。现场演示可支持流程理解，不能自动替代可复算数据或正式授权 |
| 角色模拟 | 已释放材料、项目允许的角色答复及预设可提供的例子 | 明确模拟性质，按项目规则留事实 ID。未预设文件就记未提供；不要求角色编造原件，不读取隐藏答案或未释放阶段材料来填缺口 |
| 仅分析已有资料 | 现有书面资料或问答，尚无新访谈 | 把建议问题与实际答复分开；不虚构联系人、日程、同意或访谈完成 |

| 协作方式 | AI 可以做到哪、由谁作决定 |
| --- | --- |
| 学习练习 | 按项目要求整理材料、解释方法、准备提问；学员须独立作答的模型／标准保留待作。允许怎样示范或修订以用户任务和项目约定为准 |
| 协助执行 | 在用户明确范围内起草、核查、维护模型与交接；关键业务定义与权限仍需对应依据。计划、草稿、采用和验收分别记录 |

从用户本轮要求、项目规则、当前状态和已释放文件识别情境，不重复询问已明确的信息。入口与状态不一致时列出差异及当前依据；只澄清影响范围或材料可读权限的部分，其余允许的盘点继续。通用模板不构成进入下一阶段的许可；用户只讨论工具方法时不启动客户工程。

## 2. 排序：先过滤，再按依赖和影响选择

先用材料盘点表把“已有认识—缺口—要支持的判断”连起来，再处理每个候选问题：

1. **范围是否相关、当前能不能取得？** 与本轮判断无关的列延期或不适用并写理由；未释放或不允许取得的材料保留缺口及影响，不拿其他案例或隐藏答案替代。
2. **是否已经有足够、适用且可定位的依据？** 有则标“复用已有”，现场只在需要时复述核对。旧规则是否仍适用、原件相互不同、需看实际应用等情况下可以追问，但写清新增核实目的，不能把所有已知内容再问一遍。
3. **缺它会阻塞什么？** 会改变本轮目标／可做范围，或阻塞关键业务定义、身份关系、时间条件、核对依据的，优先；只增加背景而不改变当前判断的后排。不要因为 C 编号靠前或角色职位高就优先。
4. **问题之间有什么依赖、当前角色能答什么？** 先问确定后续问题含义的前提。例如任务不清先核任务；任务已清则直接走关键工作实例，再追规则。角色答不了就询问去向并转交，不重复索取。
5. **裁成当前一轮。** 默认选最多 3 个主问题，每个只带当前相关的一两项条件追问；有约定时间和任务时调整。其余保留后台。3 是减少负担的起步建议，不是固定验收题数。

在访谈准备表为每题记录“先问／条件追问／复用已有／延期／不适用”及理由。先问列表按依赖排序；同样重要时优先当前角色可回答、能解除更多关键缺口的题。不要用全部标 P1 代替选择。

**动态分支：** 对方已给出当前版本、范围、实例和依据，就跳过等价追问；只给概念，就请求最近一次实例；出现新例外，沿该实例核条件与来源；说不掌握，记转交。缺口可保留，不以问遍清单作为完成标准。

## 3. “拿到什么才够”按要支持的判断写

每个关键缺口须有四项：**支持的判断、最少内容与核对办法、替代依据及限度、缺失影响与可继续部分。** 以下为底线方向，由 AI 结合实际任务填入项目值；一个例子能帮助理解，并不证明全量覆盖。

| 证据用途 | 最少需要与够用判断 | 可接受替代与限度 | 拿不到时 |
| --- | --- | --- | --- |
| 任务与范围 | 谁使用、要判断什么、先做到哪、暂不做什么、由谁确认及实际状态；能区分目标与承诺 | 一次明确讨论或书面需求，记录原话与范围；未确认只作拟议任务 | 先列候选范围，不能承诺交付或安排范围外操作 |
| 实际流程 | 一件近期实例的触发、输入、动作、交接、输出；每个关键环节能定位材料或说明人 | 屏幕演示、纸面、完整口述可支持描述；无计时记录不能证明效率改善 | 可整理已知步骤，缺失环节留明，不补成标准流程 |
| 身份与关联 | 记录怎样区分、互相怎样对应；有能区分同名／重复／多次事件的实例及含义 | 匿名对应记录或角色解释可支持候选；没有关联依据不能认定表可安全连接或能合并自然人 | 保留候选关系，暂缓依赖该关系的去重和计算 |
| 规则与边界 | 适用对象、条件、时点／范围、例外、依据及可解释者；用正常与相关边界实例说明算入／排除理由 | 角色口述能证明其说法或做法；不能自动替代公司制度、跨部门统一口径或正式授权 | 未核条件留未知；可先解释已知实例，不能推广为通用规则 |
| 指标与核对 | 用途、对象、窗口、范围、单位、聚合／去重、空零处理及例外；比率有分子分母，代表性同批原始记录能独立复算 | 合成实例可检验规则逻辑，但不证明生产值；只有口述或汇总数时不能声称逐条对账通过 | 可以列指标待办和未知，暂缓发布可靠数值 |
| 数据与覆盖 | 来源、记录粒度、字段解释、版本／快照、取得方式及缺项；拟用范围与实际可读范围对得上 | 元数据／导出说明可支持计划；样本不能证明全量质量，文件名不能证明内容 | 标明局部覆盖；不声称代表全业务或全历史 |
| 允许动作与阶段确认 | 谁能决定什么、允许哪些动作／对象／环境及条件，授权或核查记录可定位 | 个人意愿可作需求线索，不能替代系统权限或合同批准 | 继续范围内分析，相关外部动作保持待核 |

替代依据必须保留其证明限度，不能为了“勾已清”降格后还宣称原判断成立。模拟环境不要求真实盖章文件；若未预设所需依据，接受缺口存在，写明它阻塞哪项判断。

## 4. 从答复交接到模型与指标

用户可直接提供录音或完整沟通文本，不要求现场手写整套记录。先按 [10](10-沟通记录到业务信息.md)核实际转写／阅读范围，整理说话人、来源定位、业务候选和关键待核，完成 EX01–EX08；本节复用这些候选与索引，不再抄一遍原话。

原问题与完整答复（或已有原件）→ 带条件的候选认识 → 核查、取舍及理由 → 具体版本的模型条目 → 指标待办及未决条件。用[交接模板](../../templates/访谈到模型交接.md)记录已有编号或位置；编号示例不要求换掉项目原编号。

- 先保留原话，再区分业务陈述、个人观点、目标、授权和建模选择。一个答复可拆成多个候选，多份材料也可支持同一候选。
- 核查状态与采用状态分开；AI 提议采用不等于 FDE 已采纳，角色认可一句复述也不等于整个模型通过。
- 模型条目引用原件及取舍，指标待办引用模型版本、用途和未核条件。定义未采用时，可列待办；依赖它的正式实现与验证保持阻塞或待审。
- 新证据沿关系找受影响的模型、指标和测试，保留旧版、原失败及差异。没有指标需求就到模型为止。

这里提供交接记录方法；后续按 [07](../建模/07-指标库衔接.md)交出材料，再由 [13–15 指标库模块](../指标库/13-指标库建立手册.md)完成设计、构建、测试与验收。访谈完成本身不代表指标已实现。

## 5. 专项质量检查：出发前检查内容

逐项记录实际位置、判定和理由到访谈准备底稿。允许“待核”的业务未知，不能把未知包装成已知。判断为“待改”的问题先修订，再导出现场版。

| 编号 | 具体检查 | 能发现的错误及正确处理 |
| --- | --- | --- |
| QC01 情境 | 用户要求、项目规则、阶段释放与读取覆盖能对上吗 | 以模拟缺资料为由打开隐藏答案；应保留缺口，仅使用允许材料 |
| QC02 来源 | 每条关键已知是否回到原文，条件与信息性质是否保留 | 把一位经手人的习惯写成公司制度；应保留人、范围及未核权威性 |
| QC03 选择 | 每个先问题是否关联当前缺口和判断，有取舍理由吗 | C01–C12 全部搬入现场，或已知定义重复向每人询问；应复用已知、选最关键问题 |
| QC04 顺序 | 先后依赖、角色和回答触发条件是否明确 | 范围未定就追完整公式；应先问决定公式适用性的前提 |
| QC05 问法 | 是否能自然回答，是否夹带待证结论，是否一次塞多件事 | “所以完工就算验收，对吗？”；改问最近一单如何判断，凭什么记录 |
| QC06 取得标准 | 每项有支持判断、最少内容、替代限度、缺失影响吗 | 只有“带回规则和例子”；应明确哪些条件与哪些判断还不能支持 |
| QC07 可取得性 | 是否问对角色，是否要求超范围或不存在的材料 | 要模拟角色提供未预设的真实系统截图；改为已给实例或口述，留明不足 |
| QC08 交接 | 来源→候选→取舍→模型→指标待办可追到具体位置与版本吗 | 只写“已同步模型”，无条目或把拟议当采用；补定位和实际状态 |
| QC09 完成状态 | 准备、实际访谈、提取、采用、运行是否分开 | 问题清单存在就登记访谈完成；应看实际问答与证据 |
| QC10 现场可用 | 是否只放本轮选中问题，出处可查，细节在第二页／后台 | 两页挤满完整后台台账；应收短现场内容，另检实际分页 |

### 用正反例检验检查方法

这些是固定的判读示例，不是已经运行的 AI 测试。真正测试时保留输入、实际输出和逐项理由，不能用下面的示范结论冒充 actual。

| 情境 | 不应通过的内容／应怎样改 | 应允许的内容（防止过度拦截） |
| --- | --- | --- |
| 当前定义已有适用原件 | 原样再问“怎么定义”却无新目的；应复用来源 | 为核对实际应用而问一条边界实例，写明新增目的 |
| 来源只是一人描述 | “全公司规定如此”；改为此人的陈述并留待核 | 带原问原答与范围的候选认识 |
| 想核验收条件 | “您肯定同意完工就是验收吧”；改为中性实例问法 | 问最近一单怎样确认验收、看什么记录 |
| 模拟未提供附件 | 索要真实签章和生产截图，或编造文件；应保留未提供 | 角色可提供的预设口述实例，明确只支持其陈述 |
| 当前只有部分页可读 | 登记“全文读完”；应列已读页与未读影响 | 仅归纳已读范围，保留其余缺口 |
| 来源正确但模型未审核 | 下游写“正式口径已确认”；应保留待审及阻塞 | 记录可追溯的指标候选待办，不生成最终口径 |
| 依据足够且问题适用 | 一律判待核或拒绝整理；应按依据给出当前认识 | 复用已知、跳过等价问题，推进未被缺口阻塞的部分 |

## 6. 给 AI 的完整指令

> 先按项目规则识别真实／模拟／仅分析资料，以及学习／执行方式。按 09 和对应模板整理已给材料，不要求我先分类；每个关键认识保留原文、版本、阅读覆盖和信息性质。为缺口写清支持的判断、最少所需、替代依据及限度、缺失影响。先过滤已知、范围外和当前不能取得的事项，再按依赖与影响选少量主问题，其余列条件追问、复用或延期及理由。用业务语言准备两页现场版并作 QC01–QC10 内容检查；实际访谈后按原问答→候选→取舍→模型版本→指标待办交接。沿用已有台账，未访谈、未采用或未运行的如实保留，不代填项目要求本人作答或未释放的答案。

完整填法见[设备维修访谈准备与交接示范](../../examples/设备维修-访谈准备与交接示范.md)。来源与版本见 [SOURCES](../维护/SOURCES.md)。
