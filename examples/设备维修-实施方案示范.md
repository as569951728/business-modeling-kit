# 从材料生成实施方案：设备维修示范

**全篇为导师虚构教学材料。** 展示怎样把知识转为针对性实施方案，没有真实客户、Agent 调用、本人采用或测试通过记录。它与器材借用案例是两个独立场景，不共享规则。

## 给 AI 的任务与原始材料

请求：为下面的内部维修协作场景生成业务模型实施方案，让下一位 AI 知道该学习哪些方法、用哪些资料、交什么成果和怎样检查。本轮只准备方案，后续再按范围执行。

- R1，任务说明：调度员希望解释一张工单目前处理到哪、谁参与过哪些处理。暂不做结算、自动派工或改工单状态。
- R2，调度访谈完整片段：问“同一工单会不会换人？”答“会，第一次处理未解决，可以再派一次；每次派工都要保留，不能用后来的人覆盖前面的人。”问“那工单完成就是客户验收了？”答“我这里看到的是技师报完工，客户有没有验收还得看签认。”
- R3，演示记录说明：本演示工单编号区分工单、设备编号区分设备。一个设备可以有多张工单；每次派工有独立编号并归属一张工单。多人共同处理同一次派工的规则未说明。
- R4，样本：工单 T1、设备 D1；派工 J1 由人员 P1 处理后反馈缺配件；后来派工 J2 由 P2 处理并报完工。当前没有提供客户签认记录。
- R5，环境说明：当前只有材料文件；尚未提供 Agent 运行环境或可调用的工单系统。

期望的学习产出：不能只说“按六步建模”，必须说明重复派工、不同角色、报完工与验收的区别怎样影响任务；未知如何保留、何处需补证。

## 实施方案示范

### 1. 目的与本轮边界

为 R1 的工单处理解释任务规划业务模型。当前交付项目背景、实施方案和待核清单；不登记实际建模、模型采用或 Agent 测试完成。未来模型应能区分工单、设备与每次派工，解释处理经过及状态依据。

不做结算、自动派工或变更工单；缺签认时不能说客户已经验收。范围依据 R1–R5。

### 2. 现有资料与缺口

已有任务说明、两组完整问答、编号解释、一个重复派工样本。可据此设计身份和事件建模；不能推定多人协作数量、完整状态迁移或验收制度。

待核：向实际负责签认记录的人取得签认含义、记录实例和职责依据；向派工经手人核多人协作情形；后续如需运行，另明确可用 Agent 和数据接口。尚不知道对应人员姓名，不编造岗位名单。

### 3. 建模重点与 AI 学习方向

| 本项目问题 | 知识方向 | 拟采用的表达与检查 |
| --- | --- | --- |
| 一个设备多张工单 | K4–K6、E2 | 设备与工单分别识别，用 D1／T1 核来源；不从当前一个样本推定一对一 |
| 同工单多次派工 | E2 的重复事件与关系角色 | 以派工事件保留 J1、J2 及各自人员和结果；用“覆盖旧人员”的错误反例检查 |
| 完工与验收含义不同 | K7–K9、E1、E3 | 保留问题和回答，区分技师报完工与客户签认；不能从 R4 推出已验收 |
| 部分状态和关系未知 | E3 的范围与未知 | 多人协作、验收制度与完整状态流程列待核，不补成禁止或标准流程 |
| 没有运行环境 | E4 | 先设计知识入口与测试记录方式，实际使用保持未运行 |

以上是拟议建模选择，执行阶段仍须核查取舍。每项都对应 R1–R5，未套用器材借用的日期规则。

### 4. 执行安排

| 步骤 | 输入／要学 | 具体动作与产物 | 检查标准与阻塞处理 |
| --- | --- | --- | --- |
| S1 | R1–R5；K1–K3、E1 | 建来源索引和任务范围，保存项目背景与待核 | 每项能回到原件；缺签认不阻塞解释已知派工经过 |
| S2 | 完整问答和样本；E1 | 提取候选，保留问答上下文、事件、状态含义和未知 | 不将“是不是验收了”的提问前提记成确认；记录实际方法与结果 |
| S3 | 已核候选；E2–E3 | 草拟设备、工单、派工事件和角色关系，说明理由；FDE 核取舍 | 不覆盖 J1；不把完工当验收；关系数量未知保留；采用另记 |
| S4 | R1–R5；K11、06 | 准备正常、多次派工、状态误读、缺记录与越权的测试候选 | 期望回到 R1–R5；不能拿模型草稿自证；FDE 审关键标准 |
| S5 | 已采用模型与测试；E4 | 有环境后在正常请求中加载模型，保存请求和回答、逐题判读 | R5 当前阻塞运行；不使用示范答案冒充 actual |
| S6 | 实际失败或新材料；06 | 依影响修订模型／方法，回归相关与原正确题，保留差异 | 当前尚无实际失败；不先写修复成功或全量通过 |

执行 AI 整理和保存；FDE 判断关键取舍和测试标准；实际经手人说明业务，具备相应职责的人核实规则。姓名或权限不明时列缺口，不靠职位推定。

### 5. 独立检查和接入准备

测试候选：T1 参与过哪些处理？应保留 J1／P1 与 J2／P2 的事件联系；能否据技师报完工声称客户验收？不能，依据 R2、R4；没有签认能否证明客户拒收？不能，记录未提供不等于拒收；能否自动把 T1 关闭？不在 R1 范围，也无 R5 系统能力。

这些是从原始材料形成的 expected，actual 与 judge 仍为未运行。接入时先使用项目现有环境可支持的方式，保存实际可见的模型定义与版本；目前不预设平台、检索框架或 API。

### 6. 版本与下一步

方案 v0.1 为导师示范草稿，来源固定为本例 R1–R5，方法对应工具包 v0.2.0。下一步若进入执行，先完成 S1 来源索引并核实任务理解，再推进不受缺签认阻塞的候选与草稿；新签认材料到来时检查状态定义、任务回答和测试期望的影响。

## 自查这份方案

是否明确本轮只要方案？是否把需读知识连到本项目难点？是否区分原始事实和拟议建模选择？是否给每步输入、产物、检查和缺口处理？是否保留身份、时间或权限未知？是否把未运行留明？

这份示范可用于检查填法与教学完整性；不能充当独立新 AI 已成功执行的证据，也不能作为其他项目的业务答案。
