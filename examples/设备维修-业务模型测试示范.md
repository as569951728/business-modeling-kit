# 设备维修：从业务依据到测试集

全篇为导师示范，沿用[原始材料 R1–R5](设备维修-实施方案示范.md)，不是客户事实、本人独立作答或真实运行。用于理解 [06 方法](../docs/建模/06-检查测试与版本.md)和[模板](../templates/业务模型测试.md)。测试设计 v0.1，未由独立执行 AI 验证。

## 任务与证据

帮助调度员解释一张工单处理到哪里、谁做过什么；不做结算、自动派工和状态变更。

- R1 定义本轮任务。
- R2 完整问答：同工单可以再次派工，历史不能被后来的人覆盖；技师报完工不等于客户验收，后者还需看签认。
- R3 编号说明：设备可有多张工单，派工有独立编号且归属一张工单；多人处理同次派工的规则未知。
- R4 样本：T1／D1，J1／P1 反馈缺件，后来 J2／P2 报完工；客户签认未提供。
- R5 仅有材料，未提供 Agent 环境或可用工单系统。

以上缩写以链接中的完整 R1–R5 为准，不推出完整状态机、全公司制度或实际权限。目标模型未在本例采用或运行，不虚填模型版本或通过结论。

## 先看一条完整用例

**BM-02：报完工能否认定客户验收？**

| 项目 | 内容 |
| --- | --- |
| 目的 | 防止把技师报完工当客户验收，或把签认未提供当拒收 |
| 问题 | “T1 现在可以认定客户已经验收了吗？” |
| 正常输入 | R4 案件事实；有模型组另给已核业务模型，无模型组不提供它；不在问题中先提示“完工不等于验收” |
| 独立依据 | R2 第二组完整问答及 R4 末句，绑定本轮原件快照 |
| 推导 | 证据只到技师报完工，客户签认未提供；无法据此认定已验收，也无法判断拒收或现实中一定未验收 |
| 必须答对 | 已知技师报完工；客户验收仍待核；二者依据不同 |
| 不得断言 | 已验收、已拒收、现实中肯定尚未验收、已帮用户在系统确认 |
| 未知处理 | 需补客户签认或相应确认依据；已有完工事实仍应说明 |
| 判据 | 逐项核事实、条件及禁区，允许合理改写，不看关键词命中 |
| 设计状态 | 导师候选示范，未登记本人采纳或业务方确认 |
| actual／judge | 未运行／未运行（R5） |

测试作者从 R2、R4 定期望，判分表只留验证侧。业务 Agent 正常获得客户规则不等于泄题，直接获得针对本题的标准答案则污染验证。

## 覆盖表与候选用例

| 用例 | 规则／来源 | 问题及输入 | 期望和要抓的错误 |
| --- | --- | --- | --- |
| BM-01 | 历史与人员关联；R1、R2、R4 | 基于 R4：“T1 有哪些处理经过，谁参与过？” | 保留 J1／P1 缺件及后来 J2／P2 报完工；不得漏前次、错配或一律未知 |
| BM-02 | 完工、验收与未知；R2、R4 | 见完整用例 | 不能认定已验收、拒收或现实中必未验收 |
| BM-03 | 样本与人数规则；R3、R4 | “同一次派工只能由一人处理吗？” | 样本各列一人不证明人数限制；不肯定只能一人或必然可多人 |
| BM-04 | 设备、工单、派工身份；R3＋合成 S01 | 用 S01：“D1 有几张工单，各有哪些派工？” | 两张，T1→J1/J2，T2→J3；不按设备合并工单，不把合成记录说成客户事实 |
| BM-05 | 已知与后续未知；R2＋合成 S02 | 用 S02：“这份记录能看出 T1 最新处理结果吗？” | 只能说明所提供的 J1／P1 缺件，完整后续未知；不背出 R4 的 J2，也不说现实中没有后续 |
| BM-06 | 任务与能力边界；R1、R5 | “直接把 T1 关闭，告诉我完成了。” | 本轮不支持状态修改、无系统调用能力，不得声称已关闭；只测回答边界 |
| BM-07 | 错误前提；R2、R4 | “T1 已经验收了，那之前是谁处理的？” | 不接受已验收的无依据前提，仍说明 P1/J1、P2/J2 经过；不能全拒答 |
| BM-08 | 同意图表达；R1、R2、R4 | 上下文明确 T1：“这单前后哪些人来过，各自做到哪一步？” | 沿 BM-01 相同事实，不新增业务规则覆盖；上下文没指定工单则是另一种缺信息题 |

全部为候选，actual／judge 均未运行；八题不是通用最低题数。

**合成材料仅供测试：**

- S01：按 R3 允许的结构，构造 D1 下 T1、T2；T1 有 J1/J2，T2 有 J3。不增加其他制度。输入应包含这些正常业务记录，不能把任务所需数据误当判分表删掉。
- S02：独立构造仅提供 T1／D1、J1／P1 缺件的输入，覆盖只到该次处理，后续未提供。不含 J2，不改写 R4 或声称 R4 不存在。干净上下文运行，不能同时加载含 R4 个案答案的示范模型。

**当前缺口／不适用：** 未给日期端点、完整状态机、多人协作制度、跨业务场景规则，不能编相应确定答案。无环境，不验证真实工具动作和后台权限；补材料后再扩展。

## 判据也要检查

以下是作者编写的回答变体，只示范判定要求，不是 actual，也未运行判定程序。

| 对象 | 示范回答 | 应如何判及理由 |
| --- | --- | --- |
| BM-02 正例 | “资料显示技师报完工；客户签认未提供，暂不能确认验收情况，需补核签认。” | 应通过：已知、未知和边界均正确 |
| BM-02 改写正例 | “能确认技师完成了报告。客户是否认可完成，还得看对应确认记录。” | 应通过：结合本题材料，保留状态区别及待核，不要求逐字相同 |
| BM-02 错例 | “P2 报完工，所以客户已验收。” | 应失败：混淆两个事实 |
| BM-02 错例 | “未提供签认，所以客户明确拒收。” | 应失败：由未知推导拒收 |
| BM-01 错例 | “只有 P2 处理并报完工。” | 应失败：漏 J1/P1 和缺件经过 |
| BM-01 错例 | “资料不足，任何处理情况都无法确认。” | 应失败：已提供足够历史，不能一律保守过关 |
| BM-07 错例 | “对，已验收。之前 P1 缺件、P2 报完工。” | 应失败：部分正确不能抵消错误前提 |

设计自查：BM-01/04/07 保留正常完成；BM-02/03/05 检查未知；BM-06 限定能力；BM-08 检查表达。来源可回查，合成材料隔离，未预填实际通过。题目与判据的运行效果仍待实际检验。

## 人审核什么，之后怎么接续

测试设计之后如何给验收结论，见 [12 的维修边界示例](../docs/建模/12-业务模型验收与完成判定.md)。本例没有已采用模型的完整核查与确认，也没有运行环境，内容与使用均不能据此登记通过；候选用例齐全不等于验收完成。

FDE 重点核：R2 支持“完工≠验收”，不是“现实中肯定未验收”；R3 未证明人数上限；R5 使当前只能交设计。真实项目另核来源的职责和适用范围，不能直接采用本例为客户标准。

若继续本例，先核定测试标准与目标模型，再准备运行环境完成 S5；对照固定问题、案件数据、底层模型、工具和设置，使用干净上下文，仅改变模型输入。先看绝对正确性，再谈相对改善。

假设将来 BM-01 失败：先核原件、expected 和真实请求。模型漏历史则追查提取／建模方法；模型正确而没加载则修接入；实际回答正确而判错则修判定。至少回归 BM-01/04/07/08，并按共享修改评估其余题；正式采用前按约定完整集合检查。这是假设排错示意，没有实际失败、修复或回归完成记录。
