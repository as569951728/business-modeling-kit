# 维修指标：从材料到测试和验收记录的完整填法

**本例完全虚构，是导师教学设计；未生成实际库、未调用 Agent、未运行 judge。** 复用[维修方案](设备维修-实施方案示范.md)中“报完工与验收不同、工单有多次派工”的背景，但以下 MR 规则是新造的统计需求，不能回写成原 R1–R5 已确认。无客户数据或课程答案。

## 原始输入：新造 MR1–MR4

**逐步使用与界面：** 可打开[交互样稿](ui/review.html)体验本例 M1 核对，以及 S3 对象关系的演示草稿。每次只完成已约定一步，讲清成果、依据与未知后等使用者指示；本文件完整后续设计不是一次连续执行的授权。样稿中的选择为临时反馈，未代表本人或任何客户采用。多份签认问题沿 MR2 准备二次核实，答复尚未取得。

- **MR1 任务**：统计指定自然月的有效验收工单数，按客户签认日期归月，每工单只计一次。只支持汇总计数，不做结算或改状态。
- **MR2 记录约定**：本小样本每单最多一条有效签认；工单 ID 唯一，派工 ID 独立并指向工单。缺签认仅表示资料未知，不代表未验收；出现多条冲突签认须待核。时间采用 Asia/Shanghai，月初包含、下月初不含。这是本例的定义。
- **MR3 测试数据**：下表两张工单构成完整的本次基础测试快照，签认已提供；另列 U1 只用于未知处理设计，不混进基础总数。
- **MR4 能力约定**：计划使用支持结构化指标、时间与结果的只读问数环境；未提供实际工具及凭据，接口实现待适配。关键数据未知时停止给完整总数并说明缺口，是本例新增约定。

| 工单 | 派工 | 报完工 | 有效签认 | 用途 |
| --- | --- | --- | --- | --- |
| A | A1、A2 | 2026-11-28 | 2026-11-29 | 基础快照 |
| B | B1 | 2026-11-30 | 2026-12-01 | 基础快照 |
| U1 | U11 | 2026-11-20 | 未提供 | 单独的未知场景，不进入基础快照 |

## M0–M1：方案、口径与映射候选

本轮示范交付设计与标准，不要求实际问数。来源 MR1–MR4；业务模型背景仍引用原 R2–R3。完整运行受到 MR4 的环境缺口阻塞。

| 定义项 | 本例候选 |
| --- | --- |
| 指标 | 有效验收工单数；示意 ID accepted_work_order_count |
| 对象／去重 | 工单；按工单 ID 只计一次（MR1） |
| 时间／单位 | 有效签认日期归月，半开月窗口，张（MR1–MR2） |
| 数据映射 | 示意列 work_order_id／accepted_at；须在真实项目映射到实际字段，不拿本例当客户字典 |
| 关系 | 派工属于工单且可多次；本计数不需要关联派工表 |
| 未知 | 缺签认或冲突签认按 MR2／MR4 处理，不直接置零 |
| 依赖 | 来源事实→语义标识与时间→基础工单计数→查询指标 |

若实际原始数据已一单一条有效签认，可直接使用，派生处理不必新增。若需从多状态记录取有效签认，须有源规则再生成派生逻辑，不能随便取最大日期。

在支持 measures 的工具中，可以声明工单实体、签认时间维度，measure 按合格工单计数，simple metric 引用它。中文目录写用途、时间、单位和未知限制。这里只是候选结构，没有声称已存在可加载配置。

### 补充：先能抓错，再能区分原因

T01 同时包含重复派工与跨月，两种错误都可能返回 2。它能抓错，但单看总数不能判定哪种错误。为帮助诊断，另构造两个**独立教学快照** D-A／D-B，分别只含 A／B，覆盖明确包含 2026 年 11–12 月；仍问汇总，无新增工单筛选能力。原基础快照不改写，新 expected 只适用于相应快照。

| 用例／快照 | 问题 | 正确期望与依据 | 具体错误结果 |
| --- | --- | --- | --- |
| T05／D-A | 11 月有效验收工单数 | 1 张；A 一单且签认在月内，来自 MR1–MR3 | 把 A1、A2 的派工行当工单计数得 2；仅用报完工日期在此例仍为 1，不能用它证明时间规则 |
| T06／D-B | 11 月有效验收工单数 | 0 张；B 签认在 12 月，11 月覆盖完整且无其他工单 | 按报完工时间误计得 1；这是正常成功的零，不是未知、无覆盖或失败 |

这两项是方法示范，不是客户数据处理或课程数据替换。actual 与 judge 仍未运行。若本项目不允许另造数据，可先用授权的独立核算明细定位，并登记相应运行覆盖尚缺。

## 用户只说一句时，AI 应怎样接手

以下是基于本例材料的**拟议交互**，没有实际运行；真实项目需填自己的路径、规则与证据。

用户：“按工具包做这个项目的指标库。”

> 当前：指标库①明确任务，运行环境仍待核；可并行整理②口径。
>
> 已完成：已读 MR1–MR4；本例目标是按月汇总有效验收工单数。
>
> 尚缺／需谁：没有真实运行入口，AI 先核已有工程说明；已有材料可支持口径和独立样本设计。
>
> 流程下一步：保存项目入口和材料索引，整理口径、环境缺口及取得办法；实际问数仍未执行。

AI 将进度与材料链接存入客户指标入口，并把入口位置补充到原项目接续指引。无现成接口就保留缺口，不要求业务用户填写完整技术配置表，也不把本例的拟议设计写成已完成工程。

之后用户只说“继续这个项目”，AI 应先读该入口和新增材料。如果仍无环境且设计也未变化，就明确状态未变，继续可做的子项；若已取得接口，核证据后接续，不能重复建一套空表。
